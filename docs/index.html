⚡ Quick connect

Point any OpenAI-compatible client at the gateway. Pick your tool:

# Claude Code speaks /v1/messages natively
export ANTHROPIC_BASE_URL="https://cfrouter.workers.dev"
export ANTHROPIC_API_KEY="sk-your-gateway-token"
export ANTHROPIC_MODEL="anthropic/claude-sonnet-4-20250514"
claude  # no /v1 suffix — Claude appends it
curl -X POST https://cfrouter.workers.dev/v1/chat/completions \
  -H "Authorization: Bearer sk-your-gateway-token" \
  -d '{"model":"openai/gpt-4o","messages":[{"role":"user","content":"Hello!"}]}'
from openai import OpenAI
client = OpenAI(
    base_url="https://cfrouter.workers.dev/v1",
    api_key="sk-your-gateway-token",
)
resp = client.chat.completions.create(
    model="openai/gpt-4o",
    messages=[{"role": "user", "content": "Hello!"}],
)

Docs · Install

Deploy your own gateway.

Two paths, same result. Use the terminal if you live in it — or deploy entirely with clicks in the Cloudflare dashboard. No CLI required.

1

Clone & install

Node.js 18+ and a free Cloudflare account is all you need.

git clone https://github.com/barivanlab/cfrouter.git
cd cfrouter && npm install
2

Create the D1 database

Analytics, providers and tokens live in Cloudflare D1. Paste the returned ID into wrangler.toml.

wrangler d1 create cfrouter-db
# [[d1_databases]] binding = "DB" → database_id = "xxxx-…"
3

Set secrets

Admin password (min. 6 chars) and a random session secret (min. 16 chars). Or skip both and visit /setup — the wizard sets them in the browser.

wrangler secret put ADMIN_PASSWORD
wrangler secret put SESSION_SECRET  # openssl rand -hex 32
4

Deploy

One command — your gateway goes live on the edge.

wrangler deploy
# live at https://cfrouter.<your-subdomain>.workers.dev 🎉
5

Add provider + token

Open /admin, log in, click + Add Provider (or pick a preset), enter base URL + keys, hit Fetch Models. Then under Tokens create a client token — it starts with sk- and is shown once.

✅ Test it: open /v1/health in the browser, then send your first chat completion from the Usage section.
1–2

Log in → create a D1 database

Workers & Pages → D1 → Create database (e.g. cfrouter-db). ⚠️ Copy the Database ID — you need it later.

3–4

Create a Worker → paste the code

Workers & Pages → Create application → Workers → Create Worker → Edit code. Delete the default code and paste the entire contents of src/index.js (download the repo ZIP from GitHub if needed). Save and deploy.

5–6

Bind D1 + set secrets

Settings → Bindings → Add binding → D1, variable DB. Then Variables and Secrets → Add variable twice: ADMIN_PASSWORD and SESSION_SECRET — ✅ check Encrypt on both. Re-deploy after changing settings.

⚠️ Don't forget: tokens are shown once, always check Encrypt, and save your Database ID for troubleshooting.
7–11

Verify → admin → provider → token → use

Open https://<your-worker>.workers.dev/v1/health, then /admin. Add a provider (OpenAI https://api.openai.com/v1 · Anthropic https://api.anthropic.com/v1 · Gemini https://generativelanguage.googleapis.com/v1beta), Fetch Models, create a token under Tokens, and send the curl below.

curl -X POST https://cfrouter.workers.dev/v1/chat/completions \
  -H "Authorization: Bearer sk-your-api-key-here" \
  -d '{"model":"openai/gpt-4o","messages":[{"role":"user","content":"Hello!"}]}'
Docs · Usage

Use it as your router.

Every request needs three things: the base URL, a gateway token, and a slug/model id. Pick a slug per provider — a bare name broadcasts to all of them.

01 — BASE URL

One URL for everything

https://<your-worker>.workers.dev/v1

02 — API KEY

Gateway token, not provider key

Create it under Tokens in the dashboard. Starts with sk-.

03 — MODEL

slug/model routing

openai/gpt-4o · anthropic/claude-… · bare names broadcast round-robin.

🤖 Coding agents

Claude Code needs ANTHROPIC_BASE_URL with no /v1 suffix. Cline reads GET /v1/models for its dropdown. Continue takes an OpenAI-style entry.

export ANTHROPIC_BASE_URL="https://cfrouter.workers.dev"
export ANTHROPIC_API_KEY="sk-your-gateway-token"  # x-api-key header
export ANTHROPIC_MODEL="anthropic/claude-sonnet-4-20250514"
curl -N -X POST https://cfrouter.workers.dev/v1/chat/completions \
  -H "Authorization: Bearer sk-your-gateway-token" \
  -d '{"model":"openai/gpt-4o","stream":true,"messages":[{"role":"user","content":"Count to five."}]}'

Make it yours

Name the router whatever you like. ✏️

The worker name is yours to choose — it becomes your URL. Pick something fun, branded, or team-scoped. Nothing in the code depends on the name cfrouter.

Your gateway, your name.

Rename it at deploy time in wrangler.toml, at creation time in the dashboard, or hide the workers.dev name entirely behind your own domain.

📝 CLI — wrangler.toml

Change one line before wrangler deploy. Your URL follows the name.

name = "my-ai-gateway"
# → https://my-ai-gateway.<subdomain>.workers.dev

🖱️ Dashboard — worker name

Type any name when you Create Worker — e.g. llm-router, team-brain. D1 can stay cfrouter-db; only the worker name shapes the URL.

# optional: your own domain in wrangler.toml
routes = [
  { pattern = "api.yourdomain.com/*",
    zone_name = "yourdomain.com" }
]

Docs · FAQ

Troubleshooting, fast.

The five errors everyone hits once — and the one-line fix for each.

401 Invalid API key
You sent a provider key instead of a gateway token. Create one under Tokens in the dashboard — it starts with sk-.
404 Unknown provider slug
The slug before the slash matches no provider. The error lists the valid slugs — check the Providers tab, e.g. openai/gpt-4o not gpt-4o alone.
503 No providers available
No enabled provider (or no enabled key). Enable one in the Providers tab and re-run Fetch Models.
Agent hangs with no output
Streaming can't complete — the provider Base URL or key is wrong. Test the provider directly in the Playground tab first.
Empty model dropdown in Cline
The provider's /models is unreachable from the Worker. Models fall back to the cached Fetch Models list — re-run it.
I lost my admin password / token
Reset secrets with wrangler secret put (or re-deploy). Tokens are SHA-256 hashed and shown once — create a fresh one per client so analytics stay meaningful.
